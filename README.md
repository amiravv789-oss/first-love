# تونل معکوس TCP با گواهی TLS خودکار

ایران یک سرور داکر است. گیت‌هاب‌اکشن بیرون ایران Xray را اجرا می‌کند و با TCP + TLS + yamux به ایران وصل می‌شود. کاربر به IP ایران وصل می‌شود و ترافیک از تونل به Xray روی رانر گیت‌هاب می‌رود.

WebSocket در کار نیست. روی رانر گیت‌هاب داکر استفاده نمی‌شود.

## چه چیزهایی در این نسخه اصلاح شد

- پروکسی قبلاً با تمام شدن یک جهت، هر دو اتصال را می‌بست. برای HTTP و SOCKS و VLESS پاسخ سرور قطع می‌شد. حالا هر دو جهت تا پایان واقعی باز می‌مانند.
- گواهی TLS فقط بین گیت‌هاب و سرور ایران است. اپ VPN آن را نمی‌بیند. اگر `TUNNEL_TLS_SHA256` خالی باشد، تونل مثل قبل وصل می‌شود و سایت‌ها به خاطر این گواهی قطع نمی‌شوند.
- وابستگی Go داخل `vendor` است. بیلد داکر برای دانلود ماژول به اینترنت نیاز ندارد.
- اگر گواهی ذخیره‌شده خراب باشد، فقط همان گواهی از نو ساخته می‌شود. کلید خصوصی در لاگ چاپ نمی‌شود.
- ایجنت فقط به پورت‌های `443,8443,1080,8081` روی `127.0.0.1` وصل می‌شود، نه به هر پورت داخل رانر.
- Xray و ایجنت در یک مرحله اجرا می‌شوند. گیت‌هاب پروسه پس‌زمینه را آخر مرحله قبلی نمی‌کشد.
- Xray نسخهٔ `v26.9.30` با checksum ثابت نصب می‌شود، نه با اسکریپت متغیر.
- اجرای خودکار با هر push به `main` حذف شد تا با هر کامیت ۳۵۰ دقیقه رانر روشن نماند.
- توکن با مقایسهٔ ثابت‌زمان بررسی می‌شود و باید بین ۳۲ تا ۵۱۲ کاراکتر باشد.

## محدودیت‌ها

- رانر میزبانی‌شدهٔ گیت‌هاب موقتی است. job حداکثر ۳۵۰ دقیقه زنده است و بعد باید دوباره اجرا شود. روشن نگه‌داشتن دائمی، سهمیهٔ دقیقه را خیلی سریع تمام می‌کند.
- داکر فقط داخل کانتینر گوش می‌دهد. پورت عمومی رانفلر را خود داکر نمی‌سازد؛ باید در پنل منتشر شود.
- اگر دیسک پایدار روی `/data` نباشد، با هر جایگزینی کانتینر گواهی داخلی تونل عوض می‌شود. روی اتصال VPN اثری ندارد، مگر اینکه خودتان `TUNNEL_TLS_SHA256` را پر کرده باشید.
- VLESS و VMess اینجا TCP ساده و بدون TLS هستند. در اپ، TLS را خاموش بگذارید و encryption را `none` بگذارید. خطای credential از گواهی نمی‌آید؛ یعنی UUID یا یوزر/پس با سکرت گیت‌هاب یکی نیست.
- Xray جدید دربارهٔ VMess هشدار deprecation می‌دهد. برای استفادهٔ طولانی، VLESS کافی است.
- این بسته روی حساب واقعی رانفلر شما اجرا نشده است.

## پورت‌های داخل کانتینر

| پورت | کاربرد |
| --- | --- |
| 8787/tcp | کنترل تونل؛ گیت‌هاب به این وصل می‌شود |
| 443/tcp | VLESS |
| 8443/tcp | VMess |
| 1080/tcp | SOCKS5 |
| 8081/tcp | پروکسی HTTP |

اگر رانفلر پورت بیرونی را عوض کرد، کلاینت و `TUNNEL_ADDR` باید همان پورت بیرونی را داشته باشند، نه لزوماً شمارهٔ داخل کانتینر.

## ایران / رانفلر

پوشهٔ `iran` را به رانفلر بدهید. `Dockerfile` فقط همان‌جا است.

متغیرها:

- `TUNNEL_TOKEN` الزامی، حداقل ۳۲ کاراکتر تصادفی. همان مقدار باید سکرت گیت‌هاب باشد.
- `LISTEN_ADDR` اختیاری، پیش‌فرض `:8787`
- `PUBLIC_PORTS` اختیاری، پیش‌فرض `443,8443,1080,8081`
- `TLS_DIR` اختیاری، پیش‌فرض `/data`

کارهایی که پنل باید انجام بدهد:

1. دیسک پایدار را به مسیر `/data` وصل کنید تا `tls-cert.pem` و `tls-key.pem` بمانند.
2. این TCPها را عمومی کنید: `8787` و `443` و `8443` و `1080` و `8081`.

گواهی خودامضا فقط برای خود تونل ساخته می‌شود. لازم نیست آن را در اپ VPN وارد کنید. `TUNNEL_TLS_SHA256` را خالی بگذارید.

`BIND_HOST` را خالی بگذارید تا روی همهٔ رابط‌ها گوش بدهد. `TLS_HOSTNAMES` فقط نام اضافه روی گواهی خودامضا است و جای پین را نمی‌گیرد.

## گیت‌هاب

کل همین پوشه، از جمله `.github/workflows/tcp-reverse-tunnel.yml` و `agent/`، باید داخل ریپازیتوری باشد. workflow باید روی برنچی باشد که اکشنز آن را می‌بیند.

Secrets:

- `TUNNEL_ADDR` مثل `example.com:8787`. آدرس عمومی کنترل ایران است، نه URL و نه `tcp://`.
- `TUNNEL_TOKEN` عین توکن ایران.
- `TUNNEL_TLS_SHA256` را نسازید، یا خالی بگذارید. اپ VPN به آن نیاز ندارد.
- `VLESS_UUID`
- `VMESS_UUID`
- `SOCKS_USERNAME` و `SOCKS_PASSWORD`
- `HTTP_USERNAME` و `HTTP_PASSWORD`

UUID باید قالب استاندارد باشد. هر UUID نسخهٔ ۴ جدا برای VLESS و VMess کافی است.

اجرا: Actions → `Run TCP reverse tunnel` → Run workflow.

Xray فقط روی `127.0.0.1` رانر گوش می‌دهد. پورت عمومی، پورت ایران است.

## کلاینت

میزبان، دامنه یا IP عمومی ایران است.

- VLESS TCP، پورت عمومی 443، UUID همان `VLESS_UUID`، encryption برابر `none`، TLS خاموش، شبکه `tcp`.
- VMess TCP، پورت عمومی 8443، UUID همان `VMESS_UUID`، alterId برابر 0، security برابر `auto`، TLS خاموش.
- SOCKS5، پورت عمومی 1080، یوزر و پس همان سکرت‌ها. UDP خاموش است.
- پروکسی HTTP، پورت عمومی 8081، یوزر و پس همان سکرت‌ها.

نمونهٔ لینک VLESS، اگر پورت بیرونی واقعاً 443 باشد:

```text
vless://VLESS_UUID@IRAN_HOST:443?encryption=none&security=none&type=tcp#iran-vless
```

## امنیت

قبل از جابه‌جایی ترافیک مهم، پورت‌های پروکسی را بدون رمز کلاینت عمومی نکنید. SOCKS و HTTP یوزر و پس دارند. VLESS و VMess در اپ باید بدون TLS باشند و UUIDشان عین سکرت گیت‌هاب باشد؛ وگرنه اپ خطای credential می‌دهد و سایت باز نمی‌شود.
